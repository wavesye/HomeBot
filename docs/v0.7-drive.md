# v0.7：DRV8833 两轮底盘低速移动

用户已确认 v0.6 单电机测试通过，本版接入第二台电机。原始单电机实测记录继续保存在 [v0.6 台架文档](v0.6-bench.md#用户实机反馈2026-10-03)。

- **目标**：两轮底盘能低速前进、后退、原地转弯和停止。
- **具体内容**：DRV8833 A 通道控制左轮、B 通道控制右轮；独立校准两轮方向；默认输出 20%、上限 30%；实体按钮通过 GPIO23 常闭回路触发软件停止与故障锁定。
- **完成标准**：架空检查通过后，在平坦空地完成短距离低速动作；程序正常运行时，网页与实体按钮均能撤销输出；按断开 VM 的恢复流程复位、重启后不恢复旧动作。
- **需要用户测试**：先核对新接线与实体开关，再架空校准两轮，最后低速落地。具体验收表见第 7 节。

**默认仍是 `mock`。双轮驱动必须显式选择 `--motor drv8833-dual`。按用户当前选择，实体按钮只接一组 NC 到 GPIO23 与 GND，暂不接入 VM 电源回路；按钮与接线检查完成前不进行真实双轮测试。** v0.6 的 `drv8833`、`tb6612` 单电机模式保留。v0.8 的底盘视频遥控路线未开始；现有 Picamera2 代码保留，首次双轮验收保持摄像头关闭。

## 1. 沿用的硬件与新增准备

沿用 Pi 4B、已安装的 Raspberry Pi OS Lite、给 Pi 供电的充电宝、4 节 1.5V AA 独立电机电源、当前 **DRV8833** 模块和 ROB0005 的两台电机。Pi 充电宝仍需稳定提供 5V / 3A，已购 USB-C 适配器可备用。无需重装系统，也不复制 Mac 虚拟环境。

4 节 AA 的标称总电压是 6V，首次接线前仍需测量实际电压并核对到手电机允许范围；此前没有记录实测 VM，不能假定新电池一定不超过 6V。确认是正确的 4 节串联电池盒。两轮同时起动会增加电源和线材负担，不能把单电机能转等同于双轮供电已通过。

新增准备是一只**锁定式、带一组常闭触点（NC）的实体停止按钮**，只用于 GPIO 信号反馈。一组 NC 即可；若按钮有额外触点，本次留空，不接电池正极或 VM。按钮不承载电机电流，不要求它具有用于切断电机负载的电源触点额定值。按按钮资料确认常闭端子，并用万用表核对释放/按下状态。

当前电池盒没有电源开关，**AA 正极通过导线直接连接 DRV8833 VM**。需要实际断电时，在电池盒一侧断开供电连接或取出电池；排查、按钮复位和服务重启期间一直保持断电。程序卡死时也必须这样手动断电，GPIO 按钮不能代替这一动作。操作现有供电连接或电池本身，不靠裸线碰触、临时搭接或带电拆 GPIO 停机。电源线与端子仍需满足两台电机的供电需求。DRV8833 的芯片电流参数还受封装、散热及实际模块限制影响，不能把宣传的峰值值当成两通道持续输出能力；参考 [TI DRV8833 数据手册](https://www.ti.com/lit/ds/symlink/drv8833.pdf)。

## 2. 全部断电后，从单电机接线升级

先断开电池盒供电连接或取出电池；Pi 用 `sudo poweroff` 正常关机，完成后拔掉充电宝 USB-C。改线、拆线、安装车轮都在两路断电时进行，不带电拆 GPIO。固定底盘，首次运行时用稳定支架让两个驱动轮完全离地，不用手扶住转动的轮子。

**必须先拆掉 v0.6 将 BIN1、BIN2 接到 GND 的两根线，再把它们分别连接 GPIO5、GPIO6。** 保留接地线同时接 GPIO 会把输出短接到地。B 通道现在用于右轮，不再按单电机文档接地。

以下“左/右”均从机器人朝前行驶的方向定义。A 通道固定为左电机、B 通道固定为右电机；方向相反稍后用参数校准。BCM 编号与物理针脚分列，接线前对照板上 Pin 1 标记及 [树莓派官方 GPIO 图](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#gpio-and-the-40-pin-header)，不要根据照片翻面后的位置数针。

### DRV8833 模块接线

下表首列只列 DRV8833 模块端子。实体停止按钮使用独立的 Pi GPIO 检测回路，见后面的按钮接线表。

| DRV8833 模块端子 | Pi BCM 编号 | Pi 物理针脚 | 连接与说明 |
| --- | --- | --- | --- |
| AIN1 | 17 | 11 | 左轮输入 1，保留原单电机接线 |
| AIN2 | 27 | 13 | 左轮输入 2，保留原单电机接线 |
| BIN1 | **5** | **29** | 右轮输入 1；先移除原 GND 线 |
| BIN2 | **6** | **31** | 右轮输入 2；先移除原 GND 线 |
| STBY / nSLEEP | 22 | 15 | 两通道共用休眠控制，沿用已核对的连接；建议 10kΩ 下拉到 GND |
| GND | — | 6 | Pi GND、模块 GND 与电池负极共地 |
| VM | — | **不接 Pi** | AA 正极通过导线直连 VM，沿途没有开关，也不经过实体按钮 |
| AO1 / AO2 | — | — | 左电机两根线 |
| BO1 / BO2 | — | — | 右电机两根线 |
| 模块所有 NC | — | — | 留空；模块丝印 NC 表示不连接，与按钮常闭触点的 NC 不是一回事 |

### 独立的实体停止按钮接线

**“实体停止检测”是程序对 Pi GPIO23 输入的用途名称，不是 DRV8833 的引脚。按钮检测线不接 DRV8833 的任何端子。**

| 按钮检测信号 | Pi BCM 编号 | Pi 物理针脚 | 连接与说明 |
| --- | --- | --- | --- |
| 实体停止检测输入 | **23** | **16** | Pi 物理第 16 脚经按钮的 COM–NC 常闭触点接 Pi GND（物理第 6 脚）；详见第 3 节 |

DRV8833 直接在 AIN/BIN 上接收 PWM，**没有 TB6612 式的 PWMA、PWMB 或 VCC 接法**。Pi 的 3.3V、5V、BCM18 都不接到本模块；不得把 NC 猜作电源、PWM 或 nFAULT。继续核对模块 STBY 确实连接芯片 nSLEEP，且没有把 VM 电压上拉到 Pi GPIO 的元件或固定拉高的短接。TI 对两个 H 桥输入和 nSLEEP 的定义见 [数据手册输入控制与休眠说明](https://www.ti.com/lit/ds/symlink/drv8833.pdf)。

## 3. GPIO 软件停止按钮

本文的推荐按钮在正常释放时 NC 触点闭合；按下后断开并机械锁定，旋转或按其说明复位后重新闭合。**按钮 NC 指常闭触点；模块丝印 NC 指不连接。GPIO23 只接按钮触点，不接模块的任何 NC 引脚。** 实际 COM/NC 或端子编号需对照该按钮资料及万用表通断检查，不能从位置或编号猜测。

```text
电机供电回路：
4 节 AA 正极 ── 导线直连 ── DRV8833 VM
4 节 AA 负极 ──────────────────────────────────────────── 模块 GND

按钮检测回路：
Pi BCM23 / 物理 16 ── [按钮的一组 NC 触点] ── Pi GND / 物理 6

Pi GND、模块 GND、电池负极保持共地。
按钮不接 VM；额外按钮触点留空。
没有电源开关；排查、按钮复位和服务重启前，断开电池盒供电连接或取出电池。
```

GPIO23 使用 Pi 内部上拉：NC 正常闭合时将输入连到 GND；按下或检测线断开时变为高电平。程序检测到开路后锁定故障并撤销输出。该接法使用 [GPIO Zero 输入上拉到地的规则](https://gpiozero.readthedocs.io/en/stable/api_input.html#button)，但本项目把“断开”解释为停止事件。GPIO 检测回路不能接电池正极、VM 或 5V；Pi GPIO 是 3.3V 逻辑。

**能否省略这根检测线？当前 v0.7 的真实双轮模式（`--motor drv8833-dual`）不能省略。** 不接按钮或让 GPIO23 悬空，程序会将其视为停止回路开路：服务可启动，但会锁定故障并禁止移动。当前没有跳过检测的启动参数。尚未准备按钮时，可以使用 `mock` 模式检查网页，无需接这根线，但不会驱动真实电机。

运行真实双轮模式必须有正确的 NC 检测闭环，不能为绕过报错把 GPIO23 永久短接到 GND。开路被程序检测并锁定后，重新接通或旋回复位不会解除软件故障，不能点击方向继续运行。**按钮触发后的恢复顺序固定为：按下保持锁定 → 断开电池盒供电连接或取出电池 → VM 仍断电时排查并复位按钮 → 重启服务 → 确认 Output off 且没有 fault → 再恢复电池供电。只旋回按钮不能恢复控制。**

**这个按钮只提供软件停止反馈，不切断 VM，停止依赖程序与操作系统正常运行。** 正常运行时，检测回调先记住触发，后台每 100ms 检查并关闭 nSLEEP/PWM，还可能受调度延迟影响。Python 卡死、系统冻结或输出没有被撤销时，按按钮不能保证两轮停止，必须手动断开电池盒供电连接或取出电池，不碰触带电裸线或拆 GPIO。软件锁定不是独立硬件急停，也不能保证异常时 GPIO 已归零；恢复时仍必须先断 VM。

输出撤销或手动断电后，轮子仍靠惯性滑行，不能保证瞬间停住。此方案不是工业安全认证系统。当前也未读取 DRV8833 nFAULT，不声称监测过流、过热或堵转。

全部断电后用万用表确认：选定的按钮触点释放或复位时闭合，按下锁定时断开；按钮只接 GPIO23 与 GND，没有误接电机电源。再按供电检查流程核对电池盒供电连接、VM 极性和实际电压。若常闭端子或接线尚未确认，先停留在这一步，不给双轮上电。

## 4. 升级 Pi 软件并先检查启动状态

沿用已安装的 Pi OS Lite，通过 SSH 操作。先停止旧 Homebot 服务，再把本次 v0.7 最新源码同步到 Pi 项目目录。当前工作区更新不代表已经推送 GitHub；使用远程仓库时先确认拿到包含 `drv8833-dual` 的版本。保留 Pi 自己的 `.venv`，传送源码时排除 Mac 的 `.venv/`、`.git/`、`__pycache__/` 等环境与缓存，不重写 Pi 系统。

在 Pi 的现有项目目录激活环境后检查：

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m server.run --help
```

帮助中应包含 `drv8833-dual`、`--invert-left`、`--invert-right`。已有 GPIO Zero / lgpio 环境可继续使用；若是在新的 Pi 目录创建环境，按 [原有安装步骤](v0.6-bench.md#安装系统-gpio-库和项目环境) 使用 apt 的 `python3-gpiozero`、`python3-lgpio`、`python3-venv` 与 `--system-site-packages`，不使用 `sudo pip`。

双轮架空、电池盒供电连接已断开或电池已取出、按钮释放且检测回路闭合时启动：

```bash
python -m server.run --lan --motor drv8833-dual
```

手机与 Pi 连接同一 Wi-Fi，用终端地址、用户名 `homebot` 和本次访问码进入页面。先核对版本 V0.7、**DRV8833 · Two-wheel drive**、初始输出关闭、滑块初值 20%、上限 30%，以及实体停止没有处于断开或故障锁定状态。初始检测回路断开时服务仍可启动，但会立即锁定故障并禁止移动；不是必须看到启动失败才算保护有效。不要用 `--reload` 或多 worker。单纯运行 `python -m server.run --lan` 仍是虚拟模式，不会驱动 GPIO。

在 VM 仍断电时按一次实体停止，确认界面进入锁定状态；复位按钮后不能自动解除。随后按上一节的恢复顺序重新启动，确认无故障，再恢复电池供电。接通时两轮都应不转；若自行转动，立即断开电池盒供电连接或取出电池。

## 5. 架空校准两轮方向

软件的 `+` 表示该轮带动车身向前的方向，`−` 表示向后。首次安装时镜像摆放的电机可能需要反转其中一轮的电气极性，不能仅看从外侧观察的顺/逆时针判断。

| 网页动作 | 左轮 A | 右轮 B | 校准后的车身动作 |
| --- | --- | --- | --- |
| Forward | + | + | 前进 |
| Backward | − | − | 后退 |
| Left | − | + | 向左原地转向 |
| Right | + | − | 向右原地转向 |
| STOP | 输出关闭 | 输出关闭 | 两轮滑行停下 |

先从 20% 短按 Forward，观察两轮是否都朝让车身前进的方向转，立即松手或点 STOP。不转、嗡响或只有一轮起动时立即停止；在轮子完全停下后检查供电和接线，必要时只在 30% 上限内小步重试，不自动猛加速，不抬高上限硬冲。v0.6 的 18% 起转观察只针对当时的单电机台架，不是第二台电机或落地负载的固定启动阈值。

如果左轮极性相反，STOP 并观察两轮停稳，断开电池盒供电连接或取出电池，`Ctrl+C` 停服务后重新启动：

```bash
python -m server.run --lan --motor drv8833-dual --invert-left
```

仅右轮相反用：

```bash
python -m server.run --lan --motor drv8833-dual --invert-right
```

两轮都相反可同时加两个参数。参数仅翻转对应一轮的极性，不交换左右轮，也不改变限速。启动后仍从输出关闭开始；确认状态后恢复电池供电，再短测。若是 A/B 电机接到了错误车轮，先全部断电纠正通道接线，不用反向参数掩盖左右接错。

随后依次短测 Backward、Left、Right。**双轮模式任何方向变化前，都先 STOP，至少等 0.5 秒，并确认两轮完全停下。** Forward 到 Left 也算换方向，不能直接连续切换；程序拒绝不满足等待的请求，不替你测轮子实际速度。调整滑块仅影响下一次动作。

校准结果应记下：左轮是否反向、右轮是否反向，以及本次使用的启动命令。每次启动显式沿用已验证的参数；不要在轮子旋转时交换电机线。

## 6. 通过架空检查后再低速落地

先在架空状态确认四个方向、松手/STOP、按钮触发的软件停止与锁定、手动断 VM 恢复流程，以及正常退出均可用。电池、Pi、驱动板和线材固定牢靠，无裸露端子或线缠到轮子；保持有人看守，按钮以及用于断开供电或取出电池的位置均可及时操作。

在平坦、空旷、无台阶的地面做一次短距离前进并停止，再按“STOP、至少 0.5 秒、轮停稳”的顺序分别试后退和左右转。仍从 20% 起步，上限 30%；落地后无法起动就立即停止并记录，不通过长时间堵转或抬高上限完成测试。当前没有闭环转速控制，两轮相同 PWM 也不保证严格走直线。

本版只确认这些基本低速动作，不一边看视频一边完成路线，也不新增摄像头装车、移动供电整理或传感器功能。现有 CSI 预览可独立使用 [原有说明](pi-camera.md)，它的保留不代表 v0.8 已开始。

## 7. 用户逐步验收

| 阶段 | 需要用户做什么 | 完成标准 |
| --- | --- | --- |
| 断电接线 | 核对 A 左/B 右，先拆 B 输入原接地线；核对 BCM5/6 与 GPIO23 | 无输入短接地，NC 模块脚留空，VM/GPIO 不混接 |
| 按钮检查 | 核对一组 NC 的端子，测释放/按下通断；检查 AA 正极经导线直连 VM | 按钮只连 GPIO23 与 GND；释放闭合、按下断开，不接 VM |
| 供电检查 | 记录 4AA 的实测电压，检查两轮线材、端子及 Pi 供电 | 电机电压合适，连接牢固，无未经确认的供电条件 |
| VM 断电启动 | 断开电池盒供电连接或取出电池，再运行双轮命令，核对模式、20% 初值、30% 上限；按下再复位实体按钮 | 出现锁定；复位不恢复控制，重启前 VM 仍断电 |
| 架空校准 | 短测 Forward，按实际方向选择 invert 参数，记录最终命令 | 两轮方向与前进定义一致，启动不自转 |
| 架空动作 | 每次 STOP 等 0.5 秒且轮停稳，再测后退、左右转、松手与 STOP | 左右轮符号符合表格，停止后无新动作自动发出 |
| 按钮软件停止 | 程序正常运行、两轮低输出转动时按下按钮；随后断开电池盒供电连接或取出电池，再于 VM 断电时复位、重启 | 程序检测后撤销输出、锁定故障，轮子滑行停止；按钮本身不切 VM，输出关闭且无故障后才重新送电 |
| 手动断电 | 架空检查断开电池盒供电连接或取出电池可以切断两轮电源，保持断电直到排查和重启完成 | 软件按钮无法停止时可这样断电；不碰触裸线、不带电拆 GPIO，也不强杀程序或制造卡死来代替此检查 |
| 检测线断开 | 全部断电后断开 GPIO23 检测线，再只给 Pi 上电，VM 仍断电；检查后全部断电再恢复接线 | 控制保持故障锁定；恢复回路不自动解除，不带电改线 |
| 连接与退出 | 架空低速时锁屏/断开手机 Wi-Fi，再分别验证正常退出和重新启动 | 心跳中断后撤销输出；恢复或重启不自动移动；2 秒机制只在系统运行时成立 |
