# v0.6：树莓派单电机台架

本版目标是用原来的网页，让 **DRV8833 A 通道上的一台真实电机转动、停止**。用户提供的模块正面印有 DRV8833，背面没有 VCC、PWMA、PWMB，当前按这块模块适配。先固定裸电机做台架测试，不安装车轮、不把底盘放到地上运行，也不接第二台电机。v0.7 才做两轮底盘；OV5647 的 CSI 摄像头已作为独立修复接入，见 [CSI 预览步骤](pi-camera.md)，不纳入本页的电机台架验收。

软件默认仍是 `mock` 虚拟电机。当前模块必须显式选择 **`--motor drv8833`** 才会使用对应 GPIO 驱动；保留的 `--motor tb6612` 仅供另一种已核实的 TB6612FNG 硬件使用，接线见文末附录。**不要把 TB6612 接线或命令用于当前 DRV8833 模块：两者的 PWM 输入方式不同，选错驱动可能使调速失效。用户已明确确认单电机测试通过并要求升级 v0.7；本页保留 v0.6 的操作说明与第 6 节原始实测记录。**

**当前进展：单电机阶段已获用户确认，下一步按 [v0.7 双轮步骤](v0.7-drive.md) 核对双轮新接线（无需实体停止按钮）。** 第 2～5 节保留部署、接线和启动步骤，供复现与排查使用；未提供的观测数据仍按原记录范围保留。

## 1. 硬件与电源先核对

| 已提供的硬件 | 本版用途 |
| --- | --- |
| Raspberry Pi 4B，2GB；32GB microSD，已装 Raspberry Pi OS Lite | 运行网页、API 和 GPIO 控制，不重装现有系统 |
| 充电宝 | 用户选定的 Pi 电源，需核对稳定的 5V / 3A 输出与 USB-C 线 |
| 已购 5V / 3A USB-C 适配器 | Pi 备用电源 |
| 照片中印有 DRV8833 的焊针模块 | 只用 A 通道驱动单电机；接线前核对 STBY 与 nSLEEP 的对应关系 |
| DFRobot ROB0005 底盘中的一台 130 减速电机 | 固定在台架上测试，另一台不接 |
| 用户选定的 4 节 1.5V AA 电池 | 给电机独立供电，标称总电压 6V，通电前实测 |
| 随底盘的 5 节 AA 电池盒 | 不能简单少装一节使用，需确认已有真正的 4 节串联电池盒或正确方案 |
| OV5647 CSI 5MP 摄像头 | 本版不连接、不测试网页预览 |

还需核对齐备：适合排针的杜邦线、能可靠连接电机电流的电源线与接线端子、万用表、固定电机的夹具，以及能立即断开电机供电的开关。确认 STBY 接到 nSLEEP 后，建议加一只 **10kΩ 电阻下拉到 GND**。不要让裸板或端子接触金属台面。

用户提供的电机规格为 4.5～6V、空载约 400mA、堵转约 800mA、减速比 1:120；这些不是本项目测量值。DFRobot 当前 [ROB0005 官方表](https://wiki.dfrobot.com/rob0005/) 列出的电流和电压参数与之不同，可能存在型号或批次差异。**首次通电前核对到手电机标签或卖家对应资料**，不能用官网另一组较小电流替代到手电机的要求。

当前方案是 **Pi 用充电宝，电机用 4 节 1.5V AA**。Pi 4 的电源要求按 [官方硬件说明](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html) 核对：充电宝应能稳定输出 5V / 3A，USB-C 线也要适合该电流；“支持快充”不等于 5V 档一定足够，供电不稳时可换已购适配器排查。Pi 与电机的正电源分开，只把两边的地按接线表连通。GPIO、3.3V 针脚和 5V 针脚都不给电机供电。

4 节 AA 的 6V 是标称值，**不能假定新电池的实测电压一定不超过 6V**。接到 VM 前测量整组输出，确认处于到手电机允许范围内；超出就先不接，可改用带过流保护、能覆盖启动需求的独立稳压 5V 台架电源。还需确认使用真正的 4 节串联电池盒：5 节盒空一格通常会断路，不能随意用导线或金属片短接空位。

原套件 5 节 1.5V 碱性 AA 的标称总电压约 7.5V，超过这次电机上限，不能直接用。5 节镍氢虽常标称 6V，充满后也可能超出 6V，不能作为未经测量的替代。降低 PWM 百分比不等于把过高的供电电压降到合适范围。

DRV8833 的电机电源允许范围比本次电机更宽，但不能据此提高电机供电；芯片额定电流还与封装及散热条件有关，不能把标称峰值当作模块可持续承受的堵转电流。依据 [TI DRV8833 数据手册](https://www.ti.com/jp/lit/ds/symlink/drv8833.pdf)，输入可由 Pi 的 3.3V GPIO 控制；当前模块不外接逻辑 VCC，VM 由独立电机电源提供。照片中的 PCB 丝印用于确定适配方向，不能据此验证芯片真伪、具体封装电流能力或板内接线。

## 2. 先在 Pi 上安装软件，电机电源保持断开

用户已经安装 **Raspberry Pi OS Lite**，继续使用现有系统，不重写 microSD。Lite 没有桌面也能运行 Homebot：从电脑通过 SSH 登录 Pi，在同一 Wi-Fi 的手机浏览器打开 `--lan` 提供的地址。使用现有用户名和 Pi 的局域网 IP 登录，不假设用户名一定是 `pi`。如果尚未开通 SSH 或 Wi-Fi，按 [官方远程设置步骤](https://www.raspberrypi.com/documentation/computers/getting-started.html) 完成配置。

登录后先只读确认系统与架构：

```bash
uname -m
cat /etc/os-release
```

`aarch64` 表示 64 位内核架构；`armv7l` 常见于 32 位系统。本项目建议使用 64 位环境，但这里先核对现有安装，不要求因此重装。若依赖安装失败，保留这两条输出和错误信息再排查。以下命令都在 **Pi 的 SSH 终端**执行，不在 Mac 的项目环境里执行。

### 取得本次最新版源码

仓库地址是 [wavesye/HomeBot](https://github.com/wavesye/HomeBot)，但本次 v0.6 工作区修改尚未据此宣称已推送到远程。**只克隆远程仓库可能仍是旧版**。实测前，把本次最新版源码传到 Pi 的独立目录，例如 `~/HomeBot-v0.6`，保留 `server/`、`web/`、`tests/`、`docs/`、`requirements.txt` 和说明文件。

不要复制 Mac 的 `.venv`；虚拟环境必须在 Pi 上重新创建。传输源码时排除 `.venv/`、`.git/`、`__pycache__/`、`.pytest_cache/`、`.DS_Store` 等本机环境与缓存。传输完成后用 `python -m server.run --help` 确认 `--motor` 的选项包含 `drv8833`；只出现 `mock` 和 `tb6612` 就还是旧版，不要用它给当前电机模块通电。

已能通过 SSH 登录时，可在 **Mac 终端** 用下面的模板传送当前项目；先把最后一行的 `用户名` 与 `树莓派IP` 换成自己的值。这一步只传文件，不启动电机：

```bash
rsync -av --exclude='.venv/' --exclude='.git/' \
  --exclude='__pycache__/' --exclude='.pytest_cache/' --exclude='.DS_Store' \
  /Users/waves/Documents/ChatGPT/homebot_v1/ \
  用户名@树莓派IP:~/HomeBot-v0.6/
```

不要加 `--delete`，也不要覆盖 Pi 上已有的不同项目目录。后续回到 Pi 的 SSH 终端执行安装命令。

### 安装系统 GPIO 库和项目环境

```bash
sudo apt update
sudo apt install python3-gpiozero python3-lgpio python3-venv
cd ~/HomeBot-v0.6
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -c "import gpiozero, lgpio; print('GPIO libraries available')"
python -m server.run --help
```

`--system-site-packages` 让项目虚拟环境使用 apt 安装的 GPIO 库，这与 [GPIO Zero 官方安装说明](https://gpiozero.readthedocs.io/en/stable/installing.html) 一致。项目通过 [LGPIOFactory](https://gpiozero.readthedocs.io/en/stable/api_pins.html#lgpio) 访问 Pi 的 GPIO。不要使用 `sudo pip`，也不要为绕过导入错误而用 `sudo` 启动整个网页服务。`requirements.txt` 保留现有 OpenCV 依赖；CSI 摄像头还需系统 Picamera2 及显式后端选择，见 [CSI 预览步骤](pi-camera.md)。

如果 GPIO 提示权限不足，先运行 `groups` 检查当前用户是否属于 `gpio` 组；Pi OS 的默认用户通常已包含该组。确实缺少时，按官方 GPIO 权限说明将自己的用户名加入该组，并重新登录后重试。导入库的检查不会驱动 GPIO，也不验证接线。

### 先跑一次虚拟模式

电机电源仍断开：

```bash
python -m server.run --lan --motor mock
```

在同一 Wi-Fi 的手机打开终端地址，用 `homebot` 和终端访问码登录。确认显示 v0.6 和虚拟模式，先测试网页与 STOP。省略 `--motor` 时同样默认虚拟模式。此时不应把终端打印当成真实电机动作。测试后按 `Ctrl+C` 停止服务。

## 3. 全部断电后接线

先关闭电机电源；Pi 用 `sudo poweroff` 正常关机，等关机完成后断开 USB-C。**接线、改线或拔插模块时，两路电源都必须断开。** 固定单电机机身，轴可自由转动，手指、导线和衣物远离轴。

下面的 BCM 编号是软件使用的 GPIO 编号，“物理针脚”是 40 针排针的位置，两者不能混用。以板子的 Pin 1 标记和 [Pi 官方 GPIO 图](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#gpio-and-the-40-pin-header) 核对方向；可在 Pi 上运行 `pinout` 对照，不要仅凭照片朝向数针。Pi GPIO 是 3.3V 逻辑，官方明确要求电机经过驱动板，不能直接接 GPIO。

### 当前 DRV8833 模块接线

按模块背面丝印找引脚；正反两张照片翻面后左右会互换，不能只照照片位置接。背面照片从上到下，左列为 `NC / AIN2 / AIN1 / STBY / BIN1 / BIN2 / NC / GND`，右列为 `VM / NC / GND / AO1 / AO2 / BO2 / BO1 / GND`。`NC` 留空，不把它当作 VCC 或 PWM。

| DRV8833 模块标记 | 连接到哪里 | 用途 |
| --- | --- | --- |
| GND | Pi GND，物理针脚 **6**，并与电机电源负极共地 | 信号与电机电源的共同参考地 |
| VM | 独立电机电源正极，本次使用核对后的 4.5～6V | 电机供电，不接 Pi 的电源针脚 |
| AIN1 | BCM **17**，物理针脚 **11** | 正转时在此输出 PWM，AIN2 保持低 |
| AIN2 | BCM **27**，物理针脚 **13** | 反转时在此输出 PWM，AIN1 保持低 |
| STBY（先确认接到芯片 nSLEEP） | BCM **22**，物理针脚 **15**；建议另接 10kΩ 到 GND | 高电平唤醒，低电平休眠；不能固定拉高 |
| AO1 / AO2（部分板印 A01 / A02） | 单电机的两根线 | A 通道输出 |
| BIN1、BIN2 | GND | 未使用的 B 通道输入保持低 |
| BO1 / BO2 | 不连接 | 本版不用第二台电机 |
| 所有 NC | 不连接 | 不作电源或 PWM 使用 |

**Pi 的 3.3V、5V 和 BCM18（物理 12）都不接这块 DRV8833 模块。** 若之前按 TB6612 方案插了这些线，先按本节的两路断电流程移除，再逐项核对。

此类模块常把芯片的 `nSLEEP` 标为 STBY，**当前驱动以 STBY 确实连接到 nSLEEP 为前提**。接入 Pi 前，用商家对应原理图或断电通断测量确认该连接；同时确认板上没有把 STBY 固定拉高的跳线、短接或会把 VM 电压送到 Pi GPIO 的上拉。照片看不清芯片字样，不能靠 PCB 名称替代这些核对。若不能确认，先保持两路断电，不将 STBY 接入 Pi。不要把 NC 猜作故障输出。

通电前用万用表核对电源极性、VM 的实际电压和公共地；检查端子没有松脱和相邻针脚没有短路。测量电源输出后先关回电机电源，再接入 VM。电机电源正极不连 Pi 的 3.3V、5V 或 USB-C 正极。

## 4. 第一次真实启动

1. 电机电源开关保持关闭，先用 USB-C 给 Pi 上电。打开终端、进入源码目录、激活 Pi 自己的 `.venv`。
2. 显式选择真实驱动，保持单个服务进程，不使用 `--reload` 或多 worker：

   ```bash
   python -m server.run --lan --motor drv8833
   ```

3. 手机用本次访问码登录。确认终端选择 DRV8833，页面显示 **Single motor bench**、初始 **Output off**、滑块初值 20%、上限 40%，左右转向不能使用；`/api/status` 的 `motor_mode` 应为 `"drv8833"`。如果显示 Mock、TB6612 或启动失败，先处理原因，不打开电机电源。
4. 确认没有发出移动指令，再打开独立电机电源。电机应保持不转；若自行转动，立即关闭电机电源并检查 STBY 和接线。
5. 手边留着电机电源开关，从 20% 短按一次正转开始。手机方向键按住发出动作，松开即发送 STOP；电脑鼠标点击会持续输出，需要主动点击 STOP。
6. 如果只发出嗡声或轴不转，**立即 STOP**，不要长时间堵转。完全停止后检查固定、供电、接线和模块；需要时只在 40% 上限以内小步调整再短测。本版没有自动加速启动功能，也不通过提高上限强行启动。
7. 测反转前先 STOP，等待 **至少 0.5 秒**，同时观察轴已完全停下，再发出反向指令。若仍在滑行，继续等，不要把 0.5 秒理解成轴一定停下的保证。

“Forward / Backward”在本版表示单电机的两个旋转方向，不代表底盘前后。实际顺逆时针取决于接线与观察方向。左右转属于双电机功能，本版拒绝执行。

## 5. 停止、故障与显示含义

启动、正常 STOP、心跳超时和正常退出时，DRV8833 驱动把 STBY/nSLEEP 拉低，并将 AIN1、AIN2 的 PWM 归零；输出进入高阻休眠，电机靠惯性滑行到停下，不是瞬间机械制动。开始动作时，两路输入先保持低，拉高 nSLEEP 后等待至少 1ms，再在一个输入上输出 PWM，另一个保持低；正反向的有效占空比都受 40% 上限约束。这是 [TI 数据手册第 9 页的输入控制表与第 11 页的休眠说明](https://www.ti.com/jp/lit/ds/symlink/drv8833.pdf) 对应的控制方式。

页面显示的是**发出的方向和 PWM 输出比例**，不是转速、电流或轴已停止的实测反馈；本版没有编码器，也没有电池电量测量。Connected 只表示控制服务可通信。发现 GPIO 操作异常后系统锁定真实控制，页面不能把无法确认的输出报告为“已停止”；先断开电机电源，处理故障，再重新启动服务，不反复点击方向按钮。这里的故障锁定是软件发现异常后的处理，**当前模块没有接入或读取 nFAULT，不能据此声称已检测芯片过流、过热或电机堵转**。

2 秒心跳超时需要 Python 程序和操作系统继续运行。`kill -9`、进程冻结、系统卡死或供电异常时，软件不能保证 GPIO 已归零。10kΩ 下拉帮助引脚未被主动驱动时保持 STBY/nSLEEP 低，但不能覆盖 GPIO 被主动维持高的故障，也不能替代前面的模块上拉核对。因此本版始终在有人看守的台架上测试，需要时直接关闭独立电机电源；不要把网页 STOP 当成实体急停开关。

结束顺序：网页 STOP，确认轴停止，关闭电机电源，再在终端 `Ctrl+C` 结束服务。要改接线时再正常关闭 Pi 并拔掉 USB-C。不要带电调整电机线来改变方向。

## 6. 用户逐步验收

完成标准：同一网页能让单电机正转、停止和反转；启动不自转，松手、STOP、超时及正常退出都撤销驱动；没有未解释的启动、发热或错误。下表由用户观察真实硬件填写，代码测试不能代替它。

| 顺序 | 需要用户测试 | 预期结果 / 记录 |
| --- | --- | --- |
| 1 | 记录电机标签、电机电源类型、万用表测得的 VM 电压，并核对 DRV8833 接线表与 STBY/nSLEEP 对应关系 | 电压与到手电机相符，两路正电源分开且共地，GPIO 不受模块高电压上拉影响 |
| 2 | 先以 `mock` 启动，再按步骤切到 `drv8833`，最后开电机电源 | 模式准确，启动不自转，未自动恢复旧动作 |
| 3 | 从 20% 短测正转，松手，再测 STOP | 轴按指令转动；松手/STOP 后滑行停下；若未转立即停止并记录 |
| 4 | STOP 后等至少 0.5 秒且轴完全停下，再短测反转 | 旋转方向改变；不在转动中直接反向 |
| 5 | 核对滑块上限及左右按钮 | 输出最多 40%，无左右转控制；百分比仅为命令 |
| 6 | 在能稳定转动的低输出下，保持手边可断电，再锁屏或断开手机 Wi-Fi | 页面 STOP 或最后有效心跳满 2 秒后撤销输出，轴滑行停止；恢复网络不自动转 |
| 7 | 正常移动中在终端 `Ctrl+C`，观察轴 | 服务正常退出并撤销输出；不以强杀进程作为本版停止保证 |
| 8 | 重新启动服务、结束测试并断开电机电源 | 不自动恢复动作；电机停止，摄像头未开启 |

若有异常，先关闭电机电源，记录 Pi OS 版本、启动命令、报错原文，以及对应步骤；不要为了“测通过”延长堵转或升高电压。上表是 v0.6 原始验收清单；当前用户已确认进入 v0.7，第二台电机请按新的双轮文档接线，GPIO23 留空。

## 7. OV5647 为什么这次不接

Raspberry Pi 官方摄像头栈使用 `libcamera`、`rpicam-apps` 和 Picamera2，并列出 OV5647 支持；这不等于现有 `cv2.VideoCapture(0)` 可以直接读取 CSI 相机。参考 [官方摄像头软件文档](https://www.raspberrypi.com/documentation/computers/camera_software.html)。当前已新增可选 Picamera2 后端，保留 OpenCV 用于原环境。相机独立启动和网页验收见 [CSI 预览步骤](pi-camera.md)；本页的电机台架测试仍不点 Start camera。用户已验证底层采集与 JPEG 编码，接入后的 Pi 网页实机验收仍待完成。

## 附录：仅供另一块已核实的 TB6612FNG 模块

本节保留原硬件方案，**不适用于用户照片里的 DRV8833 模块**。只有实际换用具有 VCC、PWMA、PWMB 的 TB6612FNG 模块并核对其资料，才使用这套接线与命令。切换硬件前按第 3 节关闭两路电源，不能只改启动参数。

| TB6612FNG 模块标记 | 连接到哪里 |
| --- | --- |
| VCC | Pi 3.3V，物理 **1** |
| GND | Pi GND，物理 **6**，并与电机电源负极共地 |
| VM | 已核对电压的独立电机电源正极 |
| AIN1 | BCM **17**，物理 **11** |
| AIN2 | BCM **27**，物理 **13** |
| PWMA | BCM **18**，物理 **12** |
| STBY | BCM **22**，物理 **15**；建议另接 10kΩ 到 GND，不能固定拉高 |
| AO1 / AO2 | 单电机两根线 |
| BIN1、BIN2、PWMB | GND |
| BO1 / BO2 | 留空 |

确认模块共地、去耦元件、STBY 没有固定拉高，并核对 VCC/VM 没接反。TB6612 的 PWM 由独立 PWMA 输入控制，STOP 把 STBY 拉低进入高阻待机，依据 [Toshiba 数据手册](https://toshiba.semicon-storage.com/info/TB6612FNG_datasheet_en_20141001.pdf?did=10660&prodName=TB6612FNG)。仅在这套硬件上运行：

```bash
python -m server.run --lan --motor tb6612
```

页面与 `/api/status` 必须对应 TB6612 模式，再按照第 4～6 节的单电机流程与限制操作；把其中 `drv8833` 模式核对项替换为 `tb6612`。此方案同样没有新增实机通过结论。
